    Clase 5 — Criptografía Asimétrica II - RSA

    Módulo: Criptografía

    Repaso: ¿por qué se necesita otra base matemática?

    Diffie-Hellman y ElGamal se apoyan en la dificultad del logaritmo discreto. RSA se apoya en un problema distinto: la dificultad de factorizar números grandes.

    Ambos problemas son computacionalmente difíciles de resolver con los algoritmos clásicos conocidos, pero tienen propiedades distintas que los hacen útiles para cosas distintas. DH funciona para intercambio de claves; ElGamal para cifrado. RSA agrega algo importante: también funciona como base para firmas digitales (próxima clase).

    Fundamentos matemáticos

    Factorización de números grandes

    Multiplicar dos números primos grandes es fácil:

    p = 61,  q = 53
n = p * q = 3233

    Factorizar n para recuperar p y q es difícil. Para números de 2048 bits, ningún algoritmo clásico conocido puede factorizar en tiempo razonable.

    Esta asimetría — multiplicar es O(n2), factorizar es sub-exponencial pero inviable — es la base de RSA.

    Función de Euler φ(n)

    La función de Euler φ(n) cuenta cuántos enteros entre 1 y n son coprimos con n (es decir, mcd(k, n) = 1).

    Para un primo p: φ(p) = p - 1 (todos los enteros menores que p son coprimos con él).

    Para el producto de dos primos distintos:

    φ(n) = φ(p * q) = (p-1)(q-1)

    Este resultado es clave para RSA: si conocés p y q, podés calcular φ(n). Si sólo conocés n (sin saber p y q), calcular φ(n) es tan difícil como factorizar n.

    Teorema de Euler

    Si mcd(a, n) = 1, entonces:

    aφ(n) ≡ 1 (mod n)

    Consecuencia directa: si e * d ≡ 1 (mod φ(n)), entonces:

    aφ(n) ≡ 1 (mod n)

    (ae)d ≡ a(e * d) ≡ a(1 + k * φ(n)) ≡ a (mod n)

    Cifrar con e y descifrar con d son operaciones inversas. Esa es la esencia matemática de RSA.

    RSA — Rivest, Shamir, Adleman (1977)

    Generación de claves

    1. Elegir dos primos grandes p y q (secretos)
    2. Calcular n = p * q (módulo RSA, público)
    3. Calcular φ(n) = (p-1)(q-1) (secreto)
    4. Elegir e tal que: 1 < e < φ(n) mcd(e, φ(n)) = 1 (e y φ(n) coprimos)
    5. Calcular d = e-1 mod φ(n) (inverso multiplicativo de e)
    Clave pública:  (n, e)
Clave privada:  d  —  también requiere conocer p, q, φ(n)

    Cifrado y descifrado

    • Cifrado (Alice → Bob):
      Y = Xe mod n (usa clave pública de Bob)

    • Descifrado (Bob):
      X = Yd mod n (usa clave privada de Bob)

    La verificación se demuestra directamente del Teorema de Euler:

    C^d = (M^e)^d = M^(e×d) = M^(1 + k×φ(n)) ≡ M  (mod n)

    Ejemplo numérico

    p = 61,  q = 53
n = 61 * 53 = 3233
φ(n) = 60 * 52 = 3120

Elegir e = 17  (mcd(17, 3120) = 1)
Calcular d = 17⁻¹ mod 3120 = 2753
   verificación: 17 * 2753 = 46801 = 15 * 3120 + 1

Clave pública:  (3233, 17)
Clave privada:  2753

Cifrar X = 65:
  Y = 65¹⁷ mod 3233 = 2790

Descifrar Y = 2790:
  X = 2790²⁷⁵³ mod 3233 = 65

    Seguridad de RSA

    Por qué es difícil romperlo?

    Para romper RSA un atacante necesita calcular d a partir de (n, e). Para eso necesita φ(n). Para calcular φ(n) = (p-1)(q-1) necesita conocer p y q. Y para obtener p y q necesita factorizar n.

    La cadena de reducciones es:

    Romper RSA  →  calcular d  →  calcular φ(n)  →  factorizar n

    No se ha demostrado formalmente que romper RSA requiere factorizar n — podrían existir ataques que rompan RSA sin factorizar. Pero en la práctica, ningún ataque de ese tipo es conocido para RSA bien implementado.

    Tamaños de clave

    Tamaño de n Seguridad estimada Estado
    512 bits < 80 bits equiv. Roto (1999)
    1024 bits ~80 bits equiv. Inseguro, no recomendado
    2048 bits ~112 bits equiv. Mínimo recomendado hoy
    3072 bits ~128 bits equiv. Recomendado
    4096 bits ~140 bits equiv. Para uso a largo plazo

    Los tamaños de clave son mucho más grandes que en AES porque el problema subyacente (factorización) es más fácil que el problema que protege AES. RSA-2048 ofrece aproximadamente la misma seguridad que AES-112 — menos que AES-128.

    Ataques conocidos

    • Factorización directa: si n es pequeño o si p y q están cerca uno del otro, la factorización es viable. Por eso p y q deben ser elegidos aleatoriamente y de tamaño similar.
    • Ataque de módulo común: si dos usuarios comparten el mismo n con distintos e, un atacante puede recuperar mensajes. Cada par debe tener su propio n.
    • Exponente público pequeño: usar e pequeños con mensajes sin padding puede filtrar información. El padding (OAEP) es obligatorio en implementaciones seguras.
    • Ataque de tiempo (timing attack): medir el tiempo de descifrado puede revelar bits de d. RSA debe implementarse con técnicas de tiempo constante.

    RSA en la práctica: padding OAEP

    RSA sin padding es determinístico: el mismo texto plano siempre produce el mismo texto cifrado. Esto es un problema de seguridad — permite ataques de texto elegido y comparación de mensajes.

    En la práctica, RSA siempre se usa con un esquema de padding. El estándar actual es OAEP (Optimal Asymmetric Encryption Padding):

    M → [OAEP padding] → M' → M'e mod n → C

    OAEP agrega aleatoriedad al mensaje antes de cifrarlo, haciendo el cifrado probabilístico. El mismo texto plano cifrado dos veces produce textos cifrados distintos.

    RSA vs Diffie-Hellman vs ElGamal

    RSA Diffie-Hellman ElGamal
    Base matemática Factorización DLP DLP
    Propósito principal Cifrado + firmas Intercambio de claves Cifrado
    Determinístico Sin padding: sí No (efímero) No (efímero)
    Velocidad Lento Más rápido que RSA Similar a DH
    Tamaño de clave típico 2048-4096 bits 2048 bits 2048 bits
    Vulnerable a cuántica Sí (algoritmo de Shor) Sí (algoritmo de Shor) Sí (algoritmo de Shor)
    Uso actual TLS, certificados X.509 TLS (DH efímero) PGP, GPG

    Por qué RSA sigue siendo tan usado?

    RSA tiene una propiedad que DH/ElGamal no tienen de forma natural: la misma operación matemática sirve tanto para cifrar como para firmar. Invertir los roles de e y d permite crear firmas digitales — algo que veremos en detalle en la Clase 6.

    Además, RSA está embebido en toda la infraestructura de certificados digitales (X.509, TLS, HTTPS) desde los años 90. Su reemplazo es un proceso que llevará décadas.

    Distribución de claves: DH vs RSA

    Para qué se usa cada uno en TLS?

    DH efímero (DHE/ECDHE): establece el secreto de sesión. Cada conexión usa un par DH nuevo — esto garantiza Perfect Forward Secrecy (PFS): si la clave privada del servidor se compromete en el futuro, las sesiones pasadas no se pueden descifrar.

    RSA (o certificado con clave RSA): autentica al servidor. El cliente verifica que realmente está hablando con el servidor correcto y no con un impostor.

    TLS 1.3:
  Autenticación  →  certificado RSA/ECDSA del servidor
  Secreto de sesión  →  ECDHE (DH sobre curva elíptica)
  Cifrado de datos  →  AES-GCM o ChaCha20-Poly1305

    Cada algoritmo hace lo que sabe hacer mejor.

    Conceptos clave de esta clase

    • Factorización: multiplicar dos primos es fácil, factorizar su producto es difícil. Base de seguridad de RSA.
    • φ(n) = (p-1)(q-1): calcularla requiere conocer p y q. Sin factorizar n, es inaccesible para el atacante.
    • Teorema de Euler: aφ(n) ≡ 1 (mod n). De ahí se deduce que cifrar con e y descifrar con d son operaciones inversas.
    • RSA: generación de claves con n = p * q, cifrado Y = Xe mod n, descifrado X = Yd mod n.
    • Tamaño de clave: RSA-2048 es el mínimo recomendado hoy.
    • Padding OAEP: RSA sin padding es determinístico e inseguro. OAEP lo hace probabilístico.
    • Perfect Forward Secrecy: DH efímero garantiza que comprometer la clave privada futura no descifra sesiones pasadas.
    • RSA + DH en TLS: RSA autentica, DH efímero establece el secreto de sesión.
